## 怎么开

双击 `启动题库.cmd`（或在命令行里 `node server.js`）。

启动后控制台会打印两个地址：

```
本机打开：http://localhost:8765
手机打开（同一 WiFi）：http://192.168.x.x:8765
```

手机用**同一 WiFi** 打开第二个地址即可。电脑上做的题，手机会自动同步过来，反之亦然。

> 记不住 IP 也没关系：电脑上打开 **设置**，「手机打开」那一行显示的就是当前该输的地址。
> 路由器重启后 IP 可能会变，以设置页为准。

### 手机打不开时按顺序排查

1. **是不是同一个 WiFi**：手机连 4G / 流量、或者连的是「访客网络」，都到不了。
2. **IP 对不对**：以电脑设置页「手机打开」为准，别用 `localhost`。
3. **路由器开了 AP 隔离**：有些公司/公共 Wi-Fi 禁止设备互访。验证办法——手机连电脑开的热点，地址会变，重新看设置页。
4. **服务是不是还开着**：电脑上那个命令行窗口关掉、或重启电脑，服务就没了，重新双击 `启动题库.cmd`。
5. **防火墙**：已确认这台机器对 `node.exe` 放行了入站 TCP（公用配置文件）。换电脑/换 node 路径后可能需要重新允许。

## 手机不在同一网段怎么办

`http://局域网IP` 属于「不安全上下文」，浏览器不允许注册 Service Worker，所以**手机上没法离线缓存**。

为此提供了一个**离线单文件版**：`public/quiz-offline.html`（题库和代码已经一起内嵌进去，所以它比较大）。

1. 在电脑上把这个文件发到手机（微信传文件 / 邮件 / 数据线都行）；
2. 手机上用浏览器打开它（iOS 用 Safari → 从「文件」App 打开；Android 用系统浏览器 / Chrome）；
3. 它完全本地运行，不需要网络，记录存在手机本地；
4. 回到同一 WiFi 时，去 **设置 → 同步地址** 填 `http://电脑IP:8765`，点「立即同步」。

改了前端代码后要重新生成它：

```bash
node build-offline.js
```

## 数据在哪

- 本机服务：`data/events.json`（所有答题记录，纯文本，可直接备份/查看）
- 手机/浏览器：IndexedDB（不可用时自动退回 localStorage）
- 设置页有「导出记录」，建议每周导一次到 `qa-practice` 仓库

记录是**只追加的事件**（每题一条：`id / item / ts / k / dev`），当前状态由事件重放算出。
好处是两端合并只要取并集，永远不冲突；以后改评分规则也能重放历史。

## 外观

设置 → 外观，三档：**深色（默认）/ 浅色 / 跟随系统**。

配色全部走 CSS 变量（`--bg`、`--surface`、`--accent` 等），浅色只是 `html[data-theme="light"]` 覆盖一层变量，所以加新颜色时**不要在规则里写死色值**，否则深色下会漏一片。

主题在 `<head>` 里由一段内联脚本先写进 `<html data-theme>`，避免刷新时闪白。

## 按章节练

首页「章节进度」卡每一行都能点，点了**只练这一章**：本章的到期题 + 没做过的题，一次最多 12 道，**不占用每天 5 道新题的额度**。该章全毕业时会提示，不会重置你的进度。

章节多了（超过 3 章）时，卡片默认只露最近在学的 3 章，右上角「全部章节 ▾」就地铺开全部。

题库页（底部第二个 tab）按章折叠，默认全收起；顶部四个筛选作用在所有章节上，筛完没题的章会整章隐藏。那一页**只查阅、不放练习入口**——练题统一从首页进。

## 答题形态（选择题 / 口述）

在「设置 → 答题形态」里切，三种：

| 模式 | 行为 |
|---|---|
| **混合**（默认） | 知识点题出选择题；命令题、场景题、验收大题仍然先说后看 |
| **全选择** | 只要有选项就出选择题（命令题也变选择） |
| **全口述** | 全部先自己说，再点「看答案」自评 |

- 选择题答对记「会」、答错记「不会」，跟口述自评共用同一套间隔重复。
- 「不会，直接看答案（记为不会）」——没答出来就是不会。
- **场景题和验收大题永远不出选项**：它们的答案形状一旦变成选项，就等于提前把答案给你了，而面试官也不会给你四个选项。

## 间隔重复规则
| 自评 | 下次出现 | 连击 |
|---|---|---|
| 不会 | 当天队尾再来一次，隔天再考 | 归零 |
| 半对 | 1 天后 | 不增不减 |
| 会 | 1 → 3 → 7 → 14 → 30 天 | +1 |
| 连续 3 次「会」 | — | 毕业 |

带 `verify: true` 的命令题/代码题，必须勾「已在 VM 实机验证过」才算毕业。

## 题库文件怎么放

```
public/data/
  index.json   章节清单：id / title / 文件名
  ch01.json    第 1 章：{ "items": [...], "mc": { 题目id: 选项 } }
  ch02.json
  ...
```

页面启动先读 `index.json`，再并行读各章文件合成一份。按章拆分是为了**单个文件别大到没人愿意整份读完**
（一章一个文件就是给人和 agent 读的单位），加载方式对页面是无感的。离线单文件版会把它们重新合成一份内嵌进去。

## 加题目

改对应那章的 `public/data/chNN.json`，往 `items` 里加一条：

```json
{
  "id": "c02-q23", "ch": 2, "kind": "scenario", "level": 3, "src": "edited",
  "tag": ["网络"],
  "q": "题干",
  "a": ["要点一", "要点二"],
  "follow": ["可能的追问"],
  "verify": false
}
```

- `kind`：`concept` 知识点 / `scenario` 场景题 / `code` 命令题 / `acceptance` 验收大题
- `src`：`doc` 原文 / `edited` 原文整理 / `written` 补写（**补写的要人工审**）

选择题的选项写在同一个文件的 `mc` 里，按题目 id 关联：

```json
{ "c01-q06": { "options": ["A 说法", "B 说法", "C 说法", "D 说法"], "answer": 0 } }
```

`answer` 是正确项下标，渲染时按题目 id 稳定打乱，所以不用分散正确答案。只有 `concept` / `code` 需要写选项，`scenario` / `acceptance` 不写（写了也不会用）。

新增一章：放一个 `ch06.json` 进 `data/`，再在 `index.json` 的 `chapters` 里加一行
`{ "id": 6, "title": "磁盘管理及存储篇", "file": "ch06.json" }`。题目 id 前缀用 `c06-`、`ch` 字段写 `6`，
两处对不上 `node test/verify_quiz.js` 会直接报出来。

改完题库记得重新 `node build-offline.js`。

## 自测

改完代码或题库，跑这两套（都在本仓库里，不需要额外依赖）：

```bash
node test/verify_quiz.js          # 题库完整性 + 间隔重复逻辑 + 章节口径
node test/verify_app.js           # 前端集成（服务版）
node test/verify_app.js --offline # 前端集成（离线单文件版）
```

改了 `public/` 下任何前端文件后，先 `node build-offline.js` 再跑 `--offline` 那一条。

## 已知限制

- Service Worker 只在 HTTPS / localhost 生效，手机走局域网 HTTP 时没有自动缓存，离线靠单文件版。
- iOS 会清理长期不用的网页存储，记得定期导出。
- 服务是手动启动的，电脑关机/重启后就没了。
